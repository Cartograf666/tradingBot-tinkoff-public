# tradingBot-tinkoff-public

Публичное исследовательское дополнение к `tradingBot-tinkoff`: сбор данных песочницы и воспроизводимая проверка стратегий.

Программа получает стакан, ленту и торговые статусы через sandbox API Т-Банка. Затем моделирует сделки на записанных данных с учётом комиссии, глубины стакана и задержек. Заявки брокеру, создание счетов, пополнение и обращения к AI отсутствуют в исследовательском сценарии. Расписание, вычисления и хранение работают целиком на GitHub. Агент, включённый компьютер и внешний планировщик не нужны.

## Как устроено исследование

- Записывается вся основная торговая сессия по актуальному календарю API. Первые подготовки запланированы на 03:17/03:47/04:17 МСК для утра и 08:17/08:47/09:17 для дня, дополнительные — на 08:20/08:35 и 13:20/13:35. Они без секретов ждут 08:50/13:50; время фактической доставки события зависит от GitHub. Резервные события идут каждые пять минут с 08:50 до 09:15 и с 13:50 до 14:15; граница владения блоками — 14:00 МСК.
- Все обращения к рынку используют общую очередь: резервная попытка не отменяет работающий сбор. Поздний запуск сохраняет оставшуюся часть сессии, а утренний запуск после 14:00 выбирает дневной блок. Исходные границы дня сохраняются; пропуски не превращаются в успешное покрытие. Завершённое окно получает `SKIPPED`, подтверждённые части не записываются повторно. Резервные события уменьшают риск одиночного пропуска, но GitHub не гарантирует доставку всех событий расписания.
- В начале каждого блока программа ждёт его торгового окна, выполняет 60-секундную пробу, проверяет качество, запускает воспроизведение и подтверждает загрузку приватного архива. Только после успеха начинается основная запись. При ошибке блок останавливается.
- Ежечасный служебный отчёт проверяет реальную активность GitHub, срок следующего архива и интервалы без сохранённых данных. Недоступность проверки обозначается как UNKNOWN, а не успешная работа.
- Данные сохраняются частями до 30 минут. При дневном воспроизведении позиции и общий капитал переносятся между частями.
- Первые 10 пригодных дней относятся к DEVELOPMENT. После просмотра результатов владелец явно фиксирует версию командой `freeze`; следующие 10 новых дней составляют HOLDOUT. Программа сама не выбирает победителя и не переписывает стратегию.
- Полнота записи и качество определяют пригодность дня независимо от прибыли. Неполные дни не считаются успешными; задержки запуска GitHub могут приводить к таким пропускам.
- Две диагностические пробы и подготовка исключены из дневного воспроизведения, но их время остаётся в полном знаменателе покрытия. Для зачёта нужно не менее 99% секунд сессии и 80% пригодных секунд каждой акции; эти пороги не ослабляются из-за проверки.
- После завершения исследования новые записи не начинаются. Дополнительно действует предел 60 попыток запуска и 350 минут на один блок.

Исходный набор: SBER, GAZP, MAGN, VKCO, SMLT, AFKS. Исследовательские параметры: общий виртуальный капитал 100 000 ₽, бюджет одного входа до 4 000 ₽ и комиссия 0,05% на сторону в базовом сценарии. Это параметры модели, а не утверждение о тарифе конкретного счёта. Симуляция проверяет две гипотезы — продолжение импульса и возврат после его истощения — в базовом и стрессовом сценариях.

## Публичный код, приватные данные

Этот репозиторий содержит самостоятельный набор исходников с новой историей Git. История исходного проекта, `.env`, базы, записи рынка и личные отчёты сюда не переносятся.

Вычисления идут на стандартных `ubuntu-24.04` runners публичного репозитория. Архивы и отчёты сохраняются в **отдельном приватном репозитории того же владельца**, в draft Release `market-study-archive-v1`. Журнал исследования находится в его ветке `observation-state`. Публичных Actions artifacts с рыночными данными нет. Логи выполнения и результаты тестов публичны.

GitHub предоставляет стандартные runners для публичных репозиториев бесплатно; это не отменяет ограничения платформы и задержки расписания. [Условия оплаты GitHub Actions](https://docs.github.com/en/billing/concepts/product-billing/github-actions).

## Проверка без ключей

Нужен Node.js 25.4.0. Проверки используют локальные тестовые данные и не обращаются к брокеру.

```sh
npm ci --ignore-scripts --no-audit --no-fund
npm test
```

На GitHub: **Actions → Market study (public compute, private data) → Run workflow → mode: check**. Этот режим не требует Secrets и не собирает рынок.

## Подключение сбора

Сбор по умолчанию выключен. Для него нужны отдельный sandbox token и ключ доступа к приватному хранилищу. Режим `preflight` проверяет оба доступа и приватную запись в любое время суток. После его успеха `MARKET_STUDY_ENABLED=true` разрешает запуск по расписанию с обязательной утренней/дневной пробой. [Порядок настройки и проверки](docs/github-setup.md).

До успешной живой пробы нельзя считать поток рынка проверенным. `preflight` подтверждает доступ к API и хранилищу; `check` — сборку и программные проверки. Доходность на реальном исполнении они не подтверждают.
